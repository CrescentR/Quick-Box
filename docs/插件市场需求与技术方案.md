# QuickBox 插件市场需求与技术方案

## 1. 已确认决策

本阶段按以下决策推进：

- 插件市场要面向远程市场接口设计，不只做本地内置清单。
- 插件市场做独立页面，不合并到当前插件管理页。
- 插件安装目录使用 QuickBox app data 目录，不提供用户自定义目录。
- 卸载插件时同时删除本地插件资源。
- OCR 插件采用 RapidOCR 方案，由用户从插件市场下载扩展插件。
- 插件市场要和用户登录、用户状态、会员制一起设计。

## 2. 需求分析

### 2.1 背景

QuickBox 当前已经拥有大量内置工具。继续把 OCR、PDF、AI、数据库客户端、Docker 管理这类重型能力直接内置，会让主程序变大、启动变慢、维护边界变差。

插件市场的目标是把 QuickBox 从“内置工具合集”扩展为“工具平台”：

- 高频轻量工具继续内置。
- 中型和大型能力通过插件市场按需安装。
- 远程市场承担发现、分发、更新、权限展示和商业化入口。
- 用户体系承担登录状态、会员权益、下载权限、同步和后续付费能力。

### 2.2 当前基础

项目已有：

- `ToolPlugin`
- `PluginRegistry`
- `PluginSource = 'builtin' | 'local' | 'market'`
- 插件启停 SQLite 存储
- 插件管理页
- Tauri command 封装
- Rust + SQLite 本地能力
- 权限类型声明

项目缺少：

- 独立插件市场页面
- 远程市场 API
- 市场插件数据模型
- 插件安装状态模型
- 插件下载、校验、解压、卸载
- 插件资源目录规范
- 插件签名校验
- 外部插件运行时加载
- 用户登录态
- 会员权益模型
- 远程 API 鉴权

### 2.3 用户目标

用户需要在插件市场中完成：

- 快速发现插件。
- 判断插件是否适合自己。
- 明确插件体积、权限、依赖和风险。
- 登录后下载插件。
- 安装、启用、停用、卸载插件。
- 看到会员插件和免费插件的区别。
- 对大型插件有明确的下载、安装和资源校验反馈。

### 2.4 产品原则

1. 主程序继续保持轻量。
2. 插件市场作为独立页面，优先保证搜索、分类、安装状态和详情阅读效率。
3. 远程市场接口从第一阶段开始设计，但实现可以分阶段推进。
4. 没有签名校验和运行隔离前，不执行任意第三方代码。
5. OCR 可以先作为官方大型插件落地，避免一开始开放不可控第三方执行。
6. 所有远程插件必须展示权限、体积、网络需求、模型依赖和会员状态。
7. 用户体系和会员制从数据结构开始预留，不一开始做复杂支付闭环。

## 3. 插件市场 PRD

### 3.1 页面定位

新增独立页面：插件市场。

插件市场不替代插件管理页：

- 插件市场：发现、搜索、下载、安装、查看详情。
- 插件管理：管理已安装插件、启用、停用、卸载、查看权限。

### 3.2 导航入口

建议主导航包含：

- 启动器
- 插件市场
- 插件管理
- 设置
- 账户

如果后续导航空间紧张，可以把“插件管理”放入“插件市场”的已安装分区，但第一版建议先保持独立语义。

### 3.3 市场首页布局

插件市场首页应偏工具型，不做营销页。

首屏结构：

- 顶部：搜索框、登录状态、刷新按钮
- 左侧：分类与筛选
- 中间：插件列表
- 右侧或详情弹层：插件详情

分类：

- 全部
- 开发者基础包
- 前端增强包
- 后端增强包
- 运维排查包
- 图片处理包
- OCR 识别包
- AI 效率包
- 数据库工具包
- PDF 工具包

筛选：

- 免费
- 会员可用
- 已安装
- 未安装
- 可离线使用
- 需要网络
- 包含模型
- 需要系统权限
- 官方插件

### 3.4 插件卡片字段

插件卡片必须展示：

- 插件名称
- 简短描述
- 分类
- 作者
- 版本
- 体积
- 免费 / 会员
- 是否离线
- 是否需要网络
- 权限摘要
- 是否包含模型
- 安装状态

### 3.5 插件详情字段

插件详情必须展示：

- 插件名称
- 完整描述
- 截图或预览图
- 分类
- 标签
- 作者
- 版本
- 更新时间
- 支持平台
- 安装包大小
- 解压后大小
- 运行方式
- 权限列表
- 网络需求
- 依赖说明
- 是否包含模型
- 是否需要额外配置
- 插件包 Hash
- 签名状态
- 会员要求
- 安装目录
- 卸载说明
- 更新日志

### 3.6 插件状态

市场插件状态：

- 未安装
- 下载中
- 下载失败
- 校验中
- 校验失败
- 安装中
- 安装失败
- 已安装
- 已启用
- 已停用
- 有更新
- 资源缺失
- 会员不可用
- 需要登录

### 3.7 插件操作

免费插件：

- 未登录用户可以浏览详情。
- 是否允许未登录下载需要后续确认。建议第一版要求登录下载，方便后续会员和下载记录统一。

会员插件：

- 未登录：显示登录按钮。
- 已登录但非会员：显示开通会员按钮。
- 已登录且有权益：允许下载。

已安装插件：

- 启用
- 停用
- 卸载
- 检查更新
- 打开安装目录

卸载：

- 删除安装状态。
- 删除 app data 下对应插件资源目录。
- 删除该插件下载缓存。
- 保留用户配置与历史数据的策略需要按插件单独声明。默认第一版可以全部删除。

## 4. OCR 插件 PRD

### 4.1 插件定位

OCR 图片转文字是官方大型插件，不进入主程序内置工具。

市场展示：

- 名称：OCR 图片转文字
- 分类：OCR 识别包
- 价格类型：会员或免费待定
- 体积：50~120MB
- 运行方式：本地离线
- 网络需求：下载时需要网络，识别时不需要网络
- 权限：读文件
- 模型：包含模型
- 依赖：ONNX Runtime
- 支持语言：中文 / 英文 / 日文

### 4.2 插件包结构

按 `docs/V0.5.md` 的方向：

```text
ocr-plugin.zip
├─ plugin.json
├─ frontend/
├─ native/
│  ├─ rapidocr.exe
│  └─ onnxruntime.dll
└─ models/
   ├─ det.onnx
   ├─ rec.onnx
   └─ cls.onnx
```

### 4.3 安装流程

1. 用户进入插件市场。
2. 打开 OCR 插件详情。
3. 登录。
4. 若插件需要会员，检查会员权益。
5. 点击下载并安装。
6. 下载 `ocr-plugin.zip` 到 app data 下载缓存目录。
7. 校验 Hash。
8. 解压到 app data 插件目录。
9. 校验目录结构。
10. 写入安装状态。
11. 注册或启用 OCR 插件入口。

### 4.4 OCR 识别流程

1. 用户打开 OCR 工具视图。
2. 选择图片。
3. Rust command 检查 OCR 插件是否安装。
4. Rust command 检查 `rapidocr.exe`、`onnxruntime.dll`、模型文件是否存在。
5. Rust command 调用 RapidOCR。
6. RapidOCR 输出识别结果。
7. 前端展示文本。
8. 用户复制结果。

### 4.5 需要补充确认

实现真实 OCR 前必须确认：

- `rapidocr.exe` 的命令行参数格式。
- 输入图片路径参数名。
- 模型目录参数名。
- 输出格式是纯文本还是 JSON。
- 退出码约定。
- Windows 以外平台是否第一版支持。

没有这些精确接口前，不应猜测调用方式。

## 5. 远程市场接口设计

### 5.1 API 原则

远程市场接口应满足：

- 可分页。
- 可分类。
- 可搜索。
- 可按价格类型筛选。
- 可按平台筛选。
- 返回插件安装包 Hash。
- 返回插件权限声明。
- 返回会员要求。
- 返回下载地址。
- 支持鉴权下载。

### 5.2 核心接口

建议接口：

```text
GET /api/market/plugins
GET /api/market/plugins/{pluginId}
GET /api/market/plugins/{pluginId}/versions
POST /api/market/plugins/{pluginId}/download-token
GET /api/account/me
GET /api/account/entitlements
POST /api/auth/login
POST /api/auth/logout
POST /api/auth/refresh
```

### 5.3 市场插件字段

建议远程插件 JSON 字段：

```json
{
  "id": "official.ocr.rapidocr",
  "name": "OCR 图片转文字",
  "version": "0.1.0",
  "description": "基于 RapidOCR 的本地离线图片文字识别。",
  "author": "QuickBox",
  "category": "ocr",
  "tags": ["ocr", "image", "rapidocr"],
  "pricing": "membership",
  "requiredEntitlements": ["plugin.ocr.rapidocr"],
  "platforms": ["windows"],
  "sizeBytes": 81788928,
  "unpackedSizeBytes": 128974848,
  "offline": true,
  "requiresNetwork": false,
  "permissions": ["fs.read"],
  "containsModel": true,
  "requiresConfiguration": false,
  "runtime": "native-process",
  "dependencies": ["ONNX Runtime"],
  "latestPackage": {
    "url": "https://example.com/plugins/ocr-plugin.zip",
    "sha256": "待服务端返回精确值",
    "signature": "待服务端返回精确值"
  },
  "updatedAt": "2026-06-14T00:00:00Z"
}
```

上面是目标结构示例，不是当前可用接口。

### 5.4 本地缓存

插件市场应缓存远程清单：

- 最近一次市场列表。
- 插件详情。
- 当前用户权益。
- 下载状态。
- 安装状态。

网络不可用时：

- 市场页显示缓存内容。
- 已安装插件可继续使用。
- 需要远程权益校验的新下载不可执行。

## 6. 技术分析

### 6.1 前端模块

建议新增：

```text
src/pages/PluginMarketPage.tsx
src/pages/AccountPage.tsx
src/api/plugin-market-api.ts
src/api/account-api.ts
src/stores/plugin-market-store.ts
src/stores/account-store.ts
src/core/plugin-market/plugin-market-types.ts
```

### 6.2 Rust 模块

建议新增：

```text
src-tauri/src/commands/plugin_market.rs
src-tauri/src/commands/account.rs
src-tauri/src/storage/plugin_market_store.rs
src-tauri/src/storage/account_store.rs
```

### 6.3 SQLite 表

建议新增：

```text
plugin_market_cache
plugin_installations
account_session
account_entitlements_cache
plugin_downloads
```

`plugin_installations` 建议字段：

- `plugin_id`
- `version`
- `status`
- `enabled`
- `install_dir`
- `package_sha256`
- `installed_at`
- `updated_at`
- `last_error`

`account_session` 建议字段：

- `user_id`
- `display_name`
- `email`
- `access_token`
- `refresh_token`
- `expires_at`
- `updated_at`

Token 是否明文存储需要进一步设计。桌面端第一版可以先存 SQLite，但正式版应评估系统密钥链。

### 6.4 安装目录

使用 QuickBox app data 目录：

```text
quickbox.sqlite3
plugins/
  official.ocr.rapidocr/
    plugin.json
    frontend/
    native/
    models/
downloads/
  official.ocr.rapidocr/
    ocr-plugin.zip
```

卸载时删除：

- `plugins/{pluginId}/`
- `downloads/{pluginId}/`
- 安装状态记录

### 6.5 安全策略

第一版必须做：

- 下载 Hash 校验。
- 插件权限展示。
- 插件资源目录限制在 app data 下。
- 防止解压 Zip Slip。
- 卸载时只删除 app data 下对应插件目录。
- 网络失败和校验失败明确提示。

后续应做：

- 插件签名校验。
- 插件沙箱。
- 第三方插件审核。
- 外部 JS 运行隔离。
- 原生命令白名单。

## 7. 开发计划

### 7.1 第 1 阶段：远程市场骨架

目标：做出独立插件市场页面和远程清单读取，不安装真实插件。

任务：

1. 新增插件市场页面。
2. 新增市场插件类型。
3. 新增远程清单 API 封装。
4. 新增本地缓存降级。
5. 新增分类、搜索、筛选。
6. 新增 OCR 插件详情展示。
7. 新增登录状态占位入口。

### 7.2 第 2 阶段：账户与会员状态

目标：支持登录态、用户信息、会员权益展示。

任务：

1. 新增账户页面。
2. 新增登录 API。
3. 新增用户信息缓存。
4. 新增会员权益缓存。
5. 插件详情展示会员限制。
6. 下载前检查登录和权益。

### 7.3 第 3 阶段：插件下载与安装

目标：能下载、校验、解压、安装 OCR 插件包。

任务：

1. 新增下载 token 接口调用。
2. Rust 下载插件包。
3. 校验 SHA256。
4. 安全解压到 app data。
5. 校验插件目录结构。
6. 写入安装状态。
7. 支持卸载并删除资源。

### 7.4 第 4 阶段：OCR 运行

目标：OCR 插件安装后可识别图片。

任务：

1. 确认 RapidOCR CLI。
2. 新增 OCR command。
3. 新增 OCR 工具视图。
4. 支持选择图片。
5. 调用 RapidOCR。
6. 展示识别结果。

## 8. 仍需确认的问题

以下问题需要后续开发前确认：

1. 远程市场 API 的实际域名。
2. 登录方式：邮箱密码、验证码、OAuth，还是先用 token 输入。
3. 会员权益字段命名。
4. 免费插件是否允许未登录下载。
5. 插件包签名算法。
6. RapidOCR CLI 精确调用方式。
7. 第一版是否只支持 Windows OCR。

## 9. 当前建议

建议下一步先开发第 1 阶段：

- 独立插件市场页面。
- 使用远程市场接口结构。
- 在接口未就绪时提供本地 mock 远程响应，确保前后端流程按真实接口形状开发。
- OCR 插件先作为远程市场条目展示。
- 账户入口先显示登录状态占位。

这样可以从一开始走平台化方向，同时避免在 API、支付、OCR CLI 都未确定时把核心代码写死。
