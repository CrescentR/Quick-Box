# 内置工具开发指南

[返回首页](../README.md) · [开发环境与规范](development.md) · [构建与发布](release.md)

QuickBox 的工具由插件元数据、命令和 React 视图组成。本指南以新增一个文本整理工具为例，展示当前仓库实际使用的扩展方式。

当前工具通过源码中的 `builtin-loader.ts` 登记，随应用一起构建。`source` 类型预留了 `builtin`、`local`、`market`，`permissions` 用来声明能力需求；这些字段不等于已经实现第三方插件安装、权限执行器或安全沙箱。插件市场的后续设计见 [插件市场方案](插件市场需求与技术方案.md)。

## 1. 创建工具目录

```text
src/builtin-plugins/example-text/
├─ index.ts                插件元数据、命令与懒加载入口
└─ ExampleTextView.tsx      React 工具视图
```

建议为可复用的计算、解析和校验逻辑单独建文件；视图主要负责输入、结果和交互。现有简单示例可参考 [JSON 工具](../src/builtin-plugins/json-tool/index.ts)，多命令插件可参考 [进阶工具集](../src/builtin-plugins/advanced-tools/index.ts)。

## 2. 声明插件、命令与视图

在 `src/builtin-plugins/example-text/index.ts` 中编写：

```ts
import { lazy } from 'react'
import type { ToolPlugin } from '../../core/plugin/plugin-types'

const ExampleTextView = lazy(() => import('./ExampleTextView'))

const plugin: ToolPlugin = {
  id: 'official.example-text',
  name: '文本整理示例',
  version: '0.1.0',
  description: '移除文本首尾空白并复制结果',
  author: 'QuickBox',
  source: 'builtin',
  permissions: ['clipboard.write'],
  commands: [
    {
      id: 'official.example-text.open',
      pluginId: 'official.example-text',
      title: '文本整理示例',
      description: '移除文本首尾空白',
      keywords: ['trim', 'text', '文本', '整理', '去空白'],
      source: 'builtin',
      executeMode: 'view',
      run: async (ctx) => {
        await ctx.openView('official.example-text.view')
      },
    },
  ],
  views: [
    {
      id: 'official.example-text.view',
      title: '文本整理示例',
      component: ExampleTextView,
    },
  ],
}

export default plugin
```

接口定义以 [plugin-types.ts](../src/core/plugin/plugin-types.ts) 和 [command-types.ts](../src/core/command/command-types.ts) 为准：

| 字段 | 约定 |
| --- | --- |
| 插件 `id` | 全局唯一；内置工具沿用 `official.` 前缀 |
| 命令 `id` | 全局唯一，适合长期保持稳定；常用工具与使用记录会引用它 |
| 命令 `pluginId` | 必须对应所属插件的 `id` |
| 命令 `keywords` | 补充中英文检索词与常用术语 |
| `executeMode` | 支持 `view` 和 `immediate`；有界面时使用 `view` |
| `ctx.openView()` | 打开已注册视图，可通过第二个参数传递 `Record<string, unknown>` |
| `ctx.closeView()` | 关闭当前视图 |
| 视图 `id` | 全局唯一，与 `openView()` 的目标一致 |
| 视图 `component` | 符合 `ComponentType<PluginViewProps>`；`params` 为可选参数 |

插件与视图 ID 重复时注册中心会抛出错误。使用 React `lazy` 延迟加载视图，避免每个工具都进入初始加载路径；宿主已经提供 `Suspense` 加载提示和 `ToolErrorBoundary` 错误边界。

## 3. 实现工具视图

在 `src/builtin-plugins/example-text/ExampleTextView.tsx` 中编写：

```tsx
import { useMemo } from 'react'
import { useToolInput } from '../../core/tool/tool-context'
import { CodeBlock } from '../../ui'

export default function ExampleTextView() {
  const [input, setInput] = useToolInput('  Hello, QuickBox!  ')
  const output = useMemo(() => input.trim(), [input])

  return (
    <section className="qb-tool-view">
      <header className="qb-tool-view__header">
        <div className="qb-tool-view__header-copy">
          <div className="qb-tool-view__title">文本整理示例</div>
          <div className="qb-tool-view__description">
            移除文本首尾空白，复制结果或发送到下一步工具。
          </div>
        </div>
      </header>

      <div className="qb-tool-grid">
        <label className="qb-tool-field">
          <span className="qb-tool-label">输入</span>
          <textarea
            className="qb-tool-textarea qb-mono"
            value={input}
            onChange={(event) => setInput(event.target.value)}
          />
        </label>

        <div className="qb-tool-field">
          <span className="qb-tool-label">整理结果</span>
          <CodeBlock
            code={output}
            language="text"
            wrap
            copyable={Boolean(output)}
            resultType={output ? 'text' : undefined}
          />
        </div>
      </div>
    </section>
  )
}
```

共用组件从 `src/ui` 引入，工具布局沿用 `qb-tool-*` 样式和主题变量。上例中的 `CodeBlock` 提供复制反馈；`resultType` 让有效结果可以继续传给支持的工具。不要为错误消息设置结果类型，以免把报错当作有效输入继续处理。

## 4. 注册并加入启动器分类

在 [builtin-loader.ts](../src/core/plugin/builtin-loader.ts) 中增加导入：

```ts
import exampleText from '../../builtin-plugins/example-text'
```

然后将 `exampleText` 加入 `loadBuiltinPlugins()` 内的现有插件数组。应用初始化会调用该加载器，注册插件时也会登记其中的命令和视图。

在 [launcher-catalog.ts](../src/pages/launcher/launcher-catalog.ts) 的 `BUILTIN_TOOL_META` 中增加：

```ts
'example-text.open': ['text', FileText],
```

这个映射的键会移除命令 ID 的 `official.` 前缀。`FileText` 在当前文件中已有导入；使用其他图标时需检查并补充 `lucide-react` 导入。

现有分类为 `network`、`codec`、`text`、`time`、`dev`、`system`、`other`。未登记的命令仍能注册，但在启动器中归入「其他」。

启动应用后，搜索 `trim` 或“文本整理示例”验证入口，再在插件管理页检查名称、描述与启用状态。

## 5. 输入、草稿与工具衔接

宿主 [ToolViewPane](../src/pages/launcher/components/ToolViewPane.tsx) 为工具挂载 `ToolProvider`，上下文实现位于 [tool-context.tsx](../src/core/tool/tool-context.tsx)。

### 输入与进程内草稿

`useToolInput(initial, field)` 按以下优先级初始化输入：

1. 其他工具传入的 `params.toolInput.text`。
2. 当前进程中按 `viewId:field` 缓存的草稿。
3. 工具提供的初始值。

草稿在进程内保存，重启不会恢复；只有长度不超过 1,000,000 字符的内容进入草稿缓存。一个视图包含多个输入时，给它们不同的 `field`，避免共用草稿键。设置页提供“清除内存草稿”入口。

需要读取来源或输入类型时使用 `useToolContext()`。现有 `ToolInput` 包含 `type`、`text`、`source` 和可选 `sensitive`；类型支持 `text`、`json`、`url`、`csv`、`timestamp`、`jwt`、`cidr`。`sensitive` 会随工具传递保留，工具仍需自行避免错误持久化敏感原文。

### 保存非敏感选项

缩进、显示模式等小型选项使用 [useToolOption](../src/core/tool/use-tool-option.ts)：

```ts
const [indent, setIndent] = useToolOption<number>('example-text.indent', 2)
```

它通过工作台 store 持久化 `string | number | boolean` 预设。使用有工具前缀的稳定键，并校验取值范围。该入口用于明确选定的非敏感选项，输入原文、密码、密钥等不应作为工具预设存储。

### 接收和传递结果

结果区使用 `CodeBlock` 的 `resultType`，或直接组合 [ToolResultActions](../src/core/tool/ToolResultActions.tsx)。候选动作由 `TOOL_ACTIONS` 中声明的输入类型与目标插件启用状态共同决定。

新工具要出现在“发送到工具”列表中，还需在 `TOOL_ACTIONS` 注册 `commandId`、`title`、`accepts`；只设置 `resultType` 并不会自动把新工具变成接收目标。

传递时宿主执行目标命令，在 `openView()` 参数中加入 `toolInput` 与新的 `requestId`。超过 1,000,000 字符的结果会被拒绝传递。目标视图采用 `useToolInput` 即可沿用统一输入流程。

## 6. 调用桌面系统能力

纯文本转换优先在 TypeScript 中处理。剪贴板、磁盘文件、数据库、窗口或进程操作走现有 `src/api` 封装；缺少能力时，按 [开发指南中的 Rust 接口流程](development.md#新增-rust-能力) 新增接口。

例如，已有 [clipboard-api.ts](../src/api/clipboard-api.ts) 提供读写剪贴板的封装；工具可直接使用 [useClipboardToast](../src/hooks/useClipboardToast.tsx) 获得统一的复制反馈。`CodeBlock` 已经使用该 API 层，无需在视图另写裸 `invoke`。

在元数据中声明实际使用的权限名称，类型列表见 [permission-types.ts](../src/core/plugin/permission-types.ts)。权限声明帮助阅读和维护，系统操作的路径校验、参数限制、平台检查和失败处理仍须由 Rust 接口落实。

## 7. 完成前检查

- ID 全局唯一，命令能打开对应视图；关键词、分类、图标和描述准确。
- 工具启用或禁用后的入口与行为正确，加载中、空输入和错误状态可理解。
- 输入使用统一草稿机制；需要持久化的数据明确，敏感内容未放入工具预设。
- 结果可复制，声明的结果类型与内容一致；有工具衔接时验证接收流程。
- 纯转换与校验逻辑有必要的边界检查，关键逻辑按需添加回归测试。
- 运行 `pnpm verify`；如有 Rust 改动，另跑 Rust 单元测试并在桌面端验证系统操作。

详细检查命令、数据目录限制和故障排查见 [开发指南](development.md)。
