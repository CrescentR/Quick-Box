# 项目结构与代码入口

[文档中心](README.md) · [开发指南](development.md) · [架构概览](../ARCHITECTURE.md) · [插件开发示例](插件示范.md)

下面是当前仓库的主要源码目录。第一次参与开发，建议先按 [开发指南](development.md) 启动应用，再根据要修改的功能查找入口。

## 目录概览

```text
Quick-Box/
├── src/                        # React + TypeScript 前端
│   ├── app/                    # 初始化、应用快捷键、主题
│   ├── pages/                  # 启动器、插件管理、设置
│   │   └── launcher/           # 工具分类、搜索辅助、常用区和工具视图容器
│   ├── core/
│   │   ├── command/            # 命令类型、注册、搜索与执行
│   │   ├── plugin/             # 插件类型、内置插件加载和权限声明
│   │   ├── config/             # 配置类型与默认值
│   │   ├── tool/               # 工具上下文、选项、结果动作和内存草稿
│   │   └── workspace/          # 工作台数据类型与校验
│   ├── builtin-plugins/        # 各内置工具；index.ts 注册，View 组件呈现界面
│   ├── api/                    # Tauri 调用封装与浏览器预览适配
│   ├── stores/                 # Zustand 状态与持久化入口
│   ├── ui/                     # 共用界面组件
│   ├── styles/                 # 全局样式与主题变量
│   ├── hooks/                  # 共用 React Hooks
│   └── assets/                 # 前端静态资源
├── src-tauri/                  # Rust 桌面端与打包配置
│   ├── src/
│   │   ├── commands/           # 文件、备份、剪贴板、进程等系统命令
│   │   ├── storage/            # SQLite、迁移与数据目录管理
│   │   ├── platform/           # Windows / macOS / Unix 平台差异
│   │   ├── lib.rs              # Tauri 初始化与命令注册
│   │   ├── shortcuts.rs        # 全局快捷键
│   │   └── tray.rs             # 系统托盘
│   ├── capabilities/           # Tauri capability 配置
│   ├── windows/                # Windows 安装器 Hook
│   ├── icons/                  # 应用图标
│   ├── tauri.conf.json         # 应用与打包配置
│   └── Cargo.toml              # Rust 包与依赖
├── tests/                      # Vitest 前端及交互测试
├── scripts/                    # 开发启动、打包辅助和命令手册同步
├── .github/workflows/          # 检查与自动发行流程
├── docs/                       # 使用、开发文档与规划档案
├── public/                     # 直接提供的静态文件
├── package.json                # 版本、前端依赖与 pnpm 脚本
├── vite.config.ts              # 前端开发与构建配置
└── vitest.config.ts            # 前端测试配置
```

`node_modules/`、`dist/`、`src-tauri/target/` 和 `src-tauri/gen/` 属于依赖、构建产物或生成内容，开发时优先修改对应源码和配置。实际文件关系以导入与调用为准，目录树只列主要入口。
