# 核心组件与工具界面约定

[返回首页](../README.md) · [开发指南](development.md) · [架构说明](../ARCHITECTURE.md) · [插件开发示例](插件示范.md)

工具界面优先复用现有组件、主题变量和工具 hooks。本文列出当前代码中可直接使用的接口；各组件的完整 props 以对应 TypeScript 定义为准。

## 界面分层

| 层级 | 现有实现 | 使用方式 |
| --- | --- | --- |
| 应用布局 | `MainLayout`、`PageHeader`、`WindowShell` | 组织主页面、搜索栏和底栏 |
| 工作台容器 | `ToolViewPane` | 启动器提供标题、置顶动作、滚动区域和加载 / 错误状态 |
| 工具主体 | `qb-tool-view`、`qb-tool-grid` 等 CSS 类 | 工具提供输入、选项、结果和操作 |
| 公共 UI | `src/ui` 导出组件 | 展示代码、说明、空态、状态和反馈 |
| 工具能力 | `src/core/tool`、`useClipboardToast` | 输入草稿、选项保存、结果传递和复制反馈 |

工具主容器使用 [`tool-views.css`](../src/styles/tool-views.css) 的样式类，外层工作台由 [`ToolViewPane`](../src/pages/launcher/components/ToolViewPane.tsx) 提供。

## 公共 UI 组件

统一从 `src/ui` 导入。组件清单和导出类型见 [`src/ui/index.ts`](../src/ui/index.ts)。

| 场景 | 组件 | 说明 |
| --- | --- | --- |
| 代码 / 文本结果 | `CodeBlock` | 等宽显示、换行、行号、复制及可选结果传递；不是语法高亮编辑器 |
| 帮助说明与元数据 | `Detail`、`Markdown` | `Detail` 支持标题、简单 Markdown 和键值元数据 |
| 列表 | `List`、`ListItem` | 统一列表组织与条目展示 |
| 搜索输入 | `CommandInput` | 用于命令搜索场景；普通工具表单可使用原生输入元素 |
| 空态 / 加载 / 错误 | `EmptyState`、`LoadingState`、`Spinner`、`ErrorState` | 区分没有内容、正在处理和操作失败 |
| 反馈与标记 | `Toast`、`Tag` | 短时操作反馈与状态标签 |
| 图标和快捷键 | `Icon`、`KeyboardShortcut` | 统一图标尺寸、色调与键帽样式 |
| 操作 | `Action`、`ActionPanel` | 操作项和可搜索的动作面板 |
| 窗口 | `WindowShell`、`WindowControls` | 主页面和窗口层使用，工具内部通常不重复创建 |

`Markdown` 是轻量渲染器，支持标题、列表、段落和部分行内样式，不支持完整 GFM。Linux 命令全文单独使用 [`CommandMarkdown`](../src/builtin-plugins/command-cheatsheet-tool/CommandMarkdown.tsx) 渲染表格、代码块和链接；它跳过原始 HTML，并把图片显示为文字链接。

### 结果区示例

```tsx
import { CodeBlock, Detail } from '../../ui'

<CodeBlock
  code={result}
  language="json"
  wrap
  copyable={isValid}
  resultType={isValid ? 'json' : undefined}
/>

<Detail
  title="使用说明"
  markdown={'- 输入合法 JSON 后查看结果。\n- 结果可复制或发送到其他工具。'}
  metadata={[{ label: '处理位置', value: '本地' }]}
/>
```

`language` 用来标记内容语言；`resultType` 用来选择可接收结果的工具。只有有效结果才设置 `resultType`，避免把校验错误当成业务数据继续传递。

## 输入、选项和结果传递

### `useToolInput`：当前进程内的草稿

```tsx
import { useToolInput } from '../../core/tool/tool-context'

const [input, setInput] = useToolInput('')
const [comparison, setComparison] = useToolInput('', 'comparison')
```

草稿以 `viewId + field` 区分，先使用 `ToolProvider` 传入的 `toolInput.text`，否则恢复已有内存草稿或使用初始值。一个工具有多个字段时应指定不同的 `field`；当前实现会把传入的 `toolInput.text` 作为每个 `useToolInput` 实例的初始值，多字段工具需要自行决定接收后如何分配数据。

单份草稿只在长度不超过 `1_000_000` 个字符时保留；这个限制约束内存草稿缓存，不会阻止输入更长文本。退出应用会丢失这些草稿，设置页提供清除入口。它与用户明确保存的代码片段、命令和文件不同。

### `useToolOption`：保存非敏感预设

```tsx
import { useToolOption } from '../../core/tool/use-tool-option'

const [indent, setIndent] = useToolOption<number>('json.indent', 2)
```

只支持 `string | number | boolean`，保存到工作台的 `presets`。使用有工具前缀且稳定的 key，避免冲突；不要通过这个 hook 保存输入原文、密码、令牌或私钥。该 hook 的 setter 不返回保存 Promise；需要明确展示保存失败的操作应直接使用可处理错误的持久化入口。

### `ToolResultActions`：把结果交给下一步工具

```tsx
import { ToolResultActions } from '../../core/tool/ToolResultActions'

<ToolResultActions text={result} type="text" />
```

`CodeBlock` 设置 `resultType` 时已包含这个控件，不必重复渲染。接收工具由 `TOOL_ACTIONS` 显式登记，只列出已启用且接受该类型的目标。当前类型包括 `text`、`json`、`url`、`csv`、`timestamp`、`jwt` 和 `cidr`。

传递会携带 `toolInput`、目标 `commandId` 和新的 `requestId`，并保留已有的 `sensitive` 标记。结果超过 `1_000_000` 个字符会被拒绝；界面提示中的“1 MB”是近似说明，实际判断为字符串长度。`sensitive` 是数据标记，不会自动构成隔离或加密机制。

### `useClipboardToast`：复制与反馈

```tsx
import { useClipboardToast } from '../../hooks/useClipboardToast'

const { copyText, clipboardToast } = useClipboardToast()

<button type="button" onClick={() => void copyText(result, '转换结果')}>
  复制结果
</button>
{clipboardToast}
```

它通过 typed 剪贴板 API 写入并显示成功 / 失败反馈。`CodeBlock` 的 `copyable` 已提供复制按钮和状态，普通结果不需要再加一套重复操作。

## 布局与样式

主题值集中在 [`tokens.css`](../src/styles/tokens.css)，全局工具样式在 [`tool-views.css`](../src/styles/tool-views.css)。支持深色 / 浅色主题的组件应使用 `--qb-*` 变量，避免写死只适用于一种主题的前景色和背景色。

| 类名 | 用途 |
| --- | --- |
| `qb-tool-view` | 工具主体的纵向布局 |
| `qb-tool-view__header` / `__title` / `__description` | 工具自己的说明区 |
| `qb-tool-grid` | 输入 / 输出布局；较窄窗口折为单列 |
| `qb-tool-field` / `qb-tool-label` | 字段和标签 |
| `qb-tool-field--full` | 在网格中横跨整行 |
| `qb-tool-input` / `qb-tool-textarea` | 原生输入、选择框和文本域 |
| `qb-mono` | 等宽文本 |
| `qb-tool-actions` | 可换行操作区 |
| `qb-tool-button` / `qb-tool-button--primary` | 普通 / 主要操作 |
| `qb-tool-options` / `qb-tool-checkbox` | 选项分组 |
| `qb-tool-hint` | 补充说明 |

工具专用样式使用独立前缀，避免修改公共类后影响所有工具。长内容放入明确的结果容器，检查窄窗口下的换行、滚动和按钮可达性。

## 交互与错误处理

- 为每个输入提供可见的 `label`，为只有图标的按钮提供可访问名称；按钮明确写 `type="button"`。
- 无输入、无结果与错误分别展示；异步操作中提供加载状态，必要时禁用重复提交。
- 工具自行处理事件和异步请求失败。外层 `ToolErrorBoundary` 处理渲染错误，不会捕获按钮回调中的异步异常。
- 只在有效结果上提供复制 / 继续传递动作。文件或进程操作通过 `src/api` 调用 Rust，不在视图中散落原生 `invoke`。
- 不抢占启动器和应用已有的全局快捷键；工具内键盘操作应限制作用范围，卸载时清理事件、计时器和订阅。

工具如何注册并挂载到工作台，见 [插件开发示例](插件示范.md) 和 [React 视图渲染规则](React渲染插件View规则.md)。
